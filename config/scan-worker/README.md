# 不上传图片的速度对比测试版

此版本检测时不上传图片、不启用按需传图。文字、命中词、OCR 坐标和进度照常上报；新图片保留在台式机 `scan-worker-data/previews`，网页暂不可查看未缓存图片。已有云端预览可继续查看。请更新云端和所有台式机 JAR，Web 不需要更新。

对比同一份清单时保持机器数量、并发和规则一致，并记录缓存是否已预热；首次获取与缓存命中的时间不可直接比较。工作机每个商品输出检测耗时、本地保存及结果回传耗时。预览文件不会自动删除，不要清理本地数据目录；仍保留可用空间不足 2GB 时暂停领取的限制。

# 同一个 JAR：云端网站 + 台式机检测

两端都使用 `application.yml`，在 JAR 所在目录执行 `java -jar product_filter.jar`。台式机设置 `app.role: worker`；云端设置 `app.role: server`（未配置角色时默认云端）。无需额外配置文件、启动脚本或角色启动参数。

本次不另建检测模块、不复制 OCR 算法。`ProductDetectionEngine` 是统一参数入口，原云端检测和工作机都调用它。默认配置仍在云端执行，前端页面及原接口无需修改。

## 执行边界

云端负责登录、执行单、词库、白名单、任务调度、结果保存、复核和导出。远程模式下不先检查标题、不先获取商品，而是直接下发商品标识、该商品所有导入标题、现有进度、过滤规则和白名单快照。每次下发一个商品，不重复传整个 CSV。

台式机从头执行检测流程：处理重检/重试状态 → 检查导入标题 → 需要时发起商品获取 → 检查接口标题 → 下载图片 → OCR → 图片规则匹配 → 上报结果。导入标题命中时不会请求商品获取，也不会下载图片。

商品缓存、付费接口密钥和额度账本仍留在云端。台式机通过工作机专用 `fetch` 接口按需获取商品信息，云端仅办理缓存读取、接口代理和额度控制；是否需要获取、何时进入下一步由台式机决定。台式机不连接数据库或 Redis，任务参数中不下发第三方密钥。一个任务的获取结果（包括错误和额度不足）会复用，响应丢失重试或租约重派不会再次执行该次商品查询；用户主动新建重试任务才重新查询。

本版协议升级为 v4，云端和台式机必须同时更新同一个新 JAR。旧工作机不会被当作完整流程工作机使用；先停止旧任务，再更新两端并继续检测。

## 云端部署

1. 构建：项目根目录运行 `mvn -pl ruoyi-admin -am package`。产物 `ruoyi-admin/target/ruoyi-admin.jar`，部署时可统一命名 `product_filter.jar`。
2. 先备份当前 JAR 和配置。云端正常启动：`java -jar product_filter.jar`。
3. 将 `server.yml.example` 中配置合并到云端外置配置。配置高强度随机凭证（至少 32 个字符），例如用密码管理器生成。两端 token 填写相同的密钥；也支持在 YAML 中写 `${SCAN_WORKER_TOKEN}` 并设置对应环境变量。
4. 反向代理应转发 `/product/scan-worker/*` 到后端（通常已有 `/prod-api/` 转发），允许 `X-Scan-Worker-Token` 请求头；建议这一路径设置 `client_max_body_size 28m`。工作机支持 HTTP 和 HTTPS；路径中连续斜杠自动合并。
5. 远程模式使用 `product.scan.remote.max-inflight`，默认 32（支持 1～128），是所有工作机合计的派发上限。`product.scan.concurrency` 只控制云端本机模式，默认 3。
6. `product.scan.remote.fetch-concurrency` 默认 4，独立限制整个集群同时进入商品缓存/接口代理的请求数，避免加机器后压垮数据库或上游。它不是每秒请求数限制。

远程模式开启后先启动工作机，确认其持续领取请求成功，再让用户开始检测；未连接时云端会提示“检测工作机未连接”。不会静默切换回云端占满 CPU。

## 台式机部署（Windows x64）

1. 安装 Java 17 或更新的兼容版本；本次交付不附带 Java 安装包。
2. 将同一个 `product_filter.jar` 放到部署目录，把 `worker.yml.example` 复制为同目录的 `application.yml`。
3. 保留 `app.role: worker`，填写 `worker.server-url` 和 `worker.token`，地址中是否包含 `/prod-api` 按实际反向代理填写。
4. 在该目录执行 `java -jar product_filter.jar`，保持程序运行。无需公网 IP、入站端口或内网穿透。可按需增加内存参数：`java -Xms256m -Xmx4g -jar product_filter.jar`。

启动器使用 Spring Boot 标准配置加载机制，支持 `application.yml` / `application.yaml`、`config/` 目录、配置环境与占位符，以及 `--spring.config.location` 等标准配置参数。只读取配置，不启动 Spring 服务；`app.role: worker` 时不加载数据库和 Redis。角色拼错会报错退出；未设置角色默认云端。旧的 `worker.properties` 和 `--scan-worker` 入口已移除。

10 核 16 线程的初始配置为商品并发 4、每个 OCR 实例 1 个计算线程。16 线程不等于适合 16 个 OCR 同时跑。堆上限 4GB 不包括 ONNX/OpenCV 的原生内存；建议至少 16GB 总内存，内存较少时先设并发 2。以同一批商品比较并发 2/4/6 的总耗时、内存峰值后再调整，同时核对云端 `remote.max-inflight` 以免成为上限。尚未在用户台式机上测得最优值。

## 接入多台台式机

每台复制 JAR 和 YAML 配置即可，配置相同的云端地址和连接凭证。`worker.id` 默认 `auto`，无需填写，程序会在各自的 `worker.data-dir`（默认 `scan-worker-data`）下的 `worker-id` 生成唯一 ID，并在重启后沿用。**不要把已运行电脑的 scan-worker-data 目录复制给另一台电脑**。如需手动 ID，每台必须不同。

工作机每次进程启动还会生成会话 ID。两个进程同时使用同一工作机 ID 时，后启动进程的领取请求会被拒绝并等待重试，不会覆盖旧进程的任务。正常重启有时需等待旧会话最多约 45 秒过期。租约仍独立保留 120 秒；原机离线后，其他空闲机器可以在租约到期后接手。

有效并发上限约为 `min(在线机器配置并发之和, remote.max-inflight, 当前可用商品数)`，还受获取接口、网络和保存速度限制。比如每台并发 4，2 台最多 8、5 台最多 20、8 台最多 32；默认配置下继续加机器不会自动突破 32。该数值是保护上限，不是已证明这台云服务器能稳定承载的吞吐量。

原系统仍最多同时运行 2 个清单、另排队 20 个；本次让每个远程调度线程每次只处理一个商品，之后回到队列，避免一个大清单长期独占全部线程。不同商品使用独立锁，预览上传/结果写盘不会锁住整个调度器。一个清单内部保存仍需串行；中间进度合并为最多约每 5 秒保存一次，最终结果每次都立即保存后确认。工作机心跳和文字进度上报仍独立运行；本测试版不上传图片。

管理员可通过原登录 Token 访问 `GET /product/scan/workers`（按部署可能带 `/prod-api`），查看派发上限、各机器 ID、并发配置、当前租约数、最近心跳和在线状态。该接口只允许 admin 角色，未新增管理页面，也不会返回连接凭证。

后续大量接入时，先用实际商品压测云端 CPU、磁盘、内存和出网流量。现在仍采用整任务 JSON 快照；结果写入以及大词库反复下发可能成为瓶颈，5Mbps 公网出带宽也可能限制扩容。需要更大规模时再改为按商品增量存储、规则版本缓存或共享任务队列，不应仅不断提高并发。

## 可靠性及限制

- 任务领取有 120 秒租期，工作机每 10 秒尝试续期并上报当前商品进度。同一时间只允许一个有效租约；最多领取三次，单商品领取后最长一小时（排队等待不计入执行时限）。
- 工作机取消或租约失效后，在图片处理边界停止；正在执行的单次原生 OCR 不能保证立即中断。
- 结果先落盘到本地 outbox，云端保存原 Job 快照成功才确认完成。网络错误退避重传；同一有效租约重复完成不会重复修改结果。云端确认记录保留 10 分钟。
- 远程不可用时当前商品标为中断，停止继续领取新商品，保留已获取商品信息；重新连接后在原页面“继续检测”。不会因为重派 OCR 任务重复调用付费商品接口。
- 云端重启仍沿用原系统“任务中断、人工继续”行为，不自动恢复付费调用。工作机重启会先重传已完成的本地结果；未完成计算由云端租期到期重新派发。云端拒绝旧租约时工作机丢弃该租约的本地输出。
- 升级时旧协议的本地待传结果会移入 `obsolete-results` 保留，随后可在云端继续中断任务。最终文字记录保存在云端，预览保留在台式机；未上传的图片暂不能在网页查看。台式机磁盘剩余不足 2GB 时暂停领取。
- 当前调度针对一个云端 Java 实例。不能把多个云端实例直接接到同一任务目录；需要横向扩容时再加入共享队列。
- 云端关闭远程配置并重启即可恢复原本机检测模式；原有历史任务文件兼容。重启前停止运行中的任务。

## 工作机协议（v4）

所有请求 `POST /product/scan-worker/{operation}`，专用请求头 `X-Scan-Worker-Token`。它不是普通用户 Token；接口仅在远程模式开启时注册，并在读取请求体前验证凭证。

- `claim`：发送 `version:4, workerId, session, capacity`；空闲返回 HTTP 204，否则返回 `Input`（商品标识/已有状态、导入标题、规则、白名单、重试/重检标记、taskId、lease、expiresAt）。
- `fetch`：工作机在标题通过后按需调用，带 workerId/session/taskId/lease；返回商品快照、错误码或 quotaReached。同一任务内重试不会重复查询或扣量。
- `heartbeat`：带 workerId/session/taskId/lease；返回 accepted/cancel/expiresAt。
- `artifact`：带身份字段及 SHA-256 artifactKey、Base64 编码 JPEG artifact；只允许该商品对应数量的预览。
- `progress`：带身份字段及单商品 product 快照；只能更新当前租约对应商品。
- `complete`：不上传预览，直接提交带预览哈希和识别证据的最终 product；成功落盘返回 accepted:true。

423 表示同一机器 ID 的另一个会话仍在线：领取端等待重试，已有任务的旧会话被替换后停止。401/403 停止工作机；409/410 表示旧租约或取消；网络错误和 5xx 保留结果并重试；其他回传 4xx 停止并保留本地文件供排查。Token 不写入任务快照、结果或程序日志。

## 验证

- `mvn -pl ruoyi-admin -am package`：编译、22 项回归测试及打包（包含本地生成图片的真实 OCR 验证）。
- 构建完成后运行 `python3 config/scan-worker/verify-jar.py`：使用不带角色参数的普通命令实际启动同一个可执行 JAR 的三个独立进程，使用本地 HTTP 服务与真实调度类联调 12 个处理名额、24 个任务、心跳、台式机标题检查、命中跳过获取、台式机发起获取，以及获取响应/结果确认丢失后的重传。无需付费 API、数据库、Redis或公网请求。
- 本次验证平台为开发机 macOS；Windows 原生依赖已随 JAR 打包，但尚未在目标台式机实测。未更改线上配置或部署线上服务。
